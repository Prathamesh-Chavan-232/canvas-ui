# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Components Module

Two distinct categories of components live here with different rules.

## ui/ — shadcn/ui Primitives

**Treat as third-party code. Never edit manually.**

Generated by `npx shadcn add <component-name>`. These wrap Radix UI primitives with shadcn's styling conventions (CSS variables, CVA variants, `cn()` merging). When a Radix primitive is needed, always check if a shadcn wrapper for it already exists in `ui/` before reaching for Radix directly.

Currently installed primitives: accordion, alert-dialog, alert, button, card, checkbox, collapsible, context-menu, dialog, dropdown-menu, input, label, progress, radio-group, resizable, scroll-area, select, separator, tabs, textarea, toast/toaster, tooltip.

## common/ — App-Specific Shared Components

Application logic that is reused across multiple pages. These are **owned code** — edit freely.

### Current components

**`Layout.tsx`** — The shell for all non-builder routes. Renders the top navbar (logo + Dashboard + Settings links) and an `<Outlet />` for child routes. Pages that need the full-screen treatment (like `SiteBuilder`) are registered outside this layout in `routes.tsx`.

**`AddDialog.tsx`** — Generic modal for creating a named resource. Accepts `title: string` and `onAdd: (name: string) => void`. Used anywhere the user needs to name and create something (pages, components, projects).

### Planned builder UI components (add here)

As the site builder is developed, these specialized components belong in `common/` (or a `builder/` subfolder within `common/`):

- **ComponentPalette** — the draggable component list panel (left sidebar)
- **Canvas** — the drop target that renders the current page layout with box-model overlays
- **PropertyPanel** — the right-sidebar editor for selected component props and CVA variants
- **Toolbar** — builder-specific action bar (undo/redo, device preview toggle, export)
- **BoxModelOverlay** — the DevTools-style margin/padding outline layer rendered on top of the canvas

## Decision Rule

> If a component is a pure, unstyled interactive primitive → use/add it in `ui/`.
> If it contains app logic, state, or is specific to the builder UX → it belongs in `common/`.
